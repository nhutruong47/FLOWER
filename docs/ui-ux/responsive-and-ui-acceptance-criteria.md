## 1. Responsive Breakpoints & Viewport Matrix (`320px` to `1920px`)

Both `frontend/storefront` and `frontend/admin` are verified across the 6 viewports mandated by **Hallmark** and **Taste-Skill** (`1440x900`, `1280x800`, `1024x768`, `820x1180`, `768x1024`, `390x844`, plus `320px` overflow/collision sweep):

| Viewport Width | Target Device | Container & Grid Layout (`Storefront`) | Layout Adaptation (`Admin Workbench`) | Mandatory Geometry Rules |
|---|---|---|---|---|
| **`1920px+`** (Large Desktop) | Wide Monitor | Container capped at `--container-max: 1360px` centered; outer oat gutters grow, grid and measure never stretch (`Hallmark Floor #14`). | Left sidebar fixed (`240px`) + main workspace container capped or fluid table with pinned actions. | Equal left/right content edges (`Taste-Skill Rule #4`). |
| **`1440x900` & `1280x800`** (Standard Desktop) | Laptop / Desktop | 12-column CSS Grid (`gap: 24px`). Hero headline, sentence, primary CTA, and branch selector pill 100% visible above the fold without scrolling (`Hallmark Floor #12`). | Left navigation rail (`240px`) + 12-column workspace; full hairline data tables visible without horizontal page scroll. | `overflow-x: clip` on `html` and `body`; image grid tracks use `minmax(0, 1fr)` (`Hallmark Floor #4 & #5`). |
| **`1024x768` & `820x1180`** (Tablet Landscape / iPad Air) | Branch Counter Tablet / iPad | 8-column grid (`24px` outer padding); product grid flows 3 columns (`1024px`) or 2 columns (`820px`). | Collapsible icon+drawer sidebar so branch florists and inventory staff have full tablet width for Order Queue and Stock Transfers. | Touch targets `>= 44px × 44px` with `>= 8px` gap between interactive targets. |
| **`768x1024`** (Tablet Portrait) | Tablet Portrait | 2-column product grid (`24px` padding); Stage hero stacks text first, daylight bouquet photo second (`Taste-Skill §5`). | Sidebar collapses into top drawer button; filter bars wrap cleanly into 2 rows; data tables scroll horizontally inside their own `overflow-x: auto` hairline wrapper (never scrolling the page viewport). | Zero overlapping elements (`{collide}` = 0). |
| **`390x844` & `320px`** (Mobile Phone) | Customer & Delivery Rider Phone | 1-column layout (`16px` left/right padding); full-width pill buttons; sticky top **Branch Price Pill** + bottom sticky mobile checkout/bag bar; full-screen mobile navigation drawer. | Mobile-optimized views for **`DELIVERY_STAFF`** (`/admin/deliveries`), **`SALES_STAFF`** pickup verification, and **`INVENTORY_STAFF`** stock-in/spoilage entry: tables collapse key fields into stacked hairline cards with full-width action buttons. | Zero horizontal overflow at `320px` (`[off-viewport]` = 0); all inputs `font-size: 16px` (`1rem`) to prevent iOS auto-zoom. |

## 2. Testable UI/UX Acceptance Criteria (`UI-AC-01` to `UI-AC-12`)

Every UI acceptance criterion below maps to our P04 requirements (`REQ-001`..`017`, `FR-001`..`038`, `NFR-002`, `NFR-008`, `NFR-013`) and will be verified in Phases 8–10 via **Vitest component tests**, **Playwright E2E tests (`TEST-015`, `TEST-019`)**, and the **Hallmark / Taste-Skill browser checkers**:

| ID | Linked `REQ` / `FR` / `NFR` | Testable Acceptance Criterion (Given / When / Then) | Verification Method |
|---|---|---|---|
| **UI-AC-01** *(App Isolation)* | `DEC-005`, `NFR-002` | **Given** `frontend/storefront` and `frontend/admin` are built for production, **when** the module import graph and output bundles are inspected, **then** neither app imports any file from the other, and all shared code comes exclusively from `frontend/packages/shared`. | Vite production build + ESLint boundary rule |
| **UI-AC-02** *(Per-Branch Storefront Pricing)* | `REQ-004`, `REQ-017`, `FR-014`, `TEST-019` | **Given** Branch A prices Product P at `450,000 VND` and Branch B prices Product P at `500,000 VND`, **when** a customer switches the `BranchPriceSelectorBar` from Branch A to Branch B on the storefront, **then** all displayed prices and stock counts update immediately to Branch B's values. | Vitest + Playwright E2E (`TEST-019`) |
| **UI-AC-03** *(Delivery vs. Pickup & Auto-Branch Allocation)* | `REQ-005`, `REQ-012`, `REQ-013`, `REQ-014`, `FR-021`, `TEST-015` | **Given** a customer on `/checkout`, **when** they choose `Home Delivery`, **then** no manual fulfilling-branch selector is offered and the checkout request never trusts a client-selected fulfilling branch; **when** they choose `In-Store Pickup`, **then** only active branches holding sufficient stock for the cart are selectable as the pickup store. | Vitest + Playwright E2E (`TEST-015`) |
| **UI-AC-04** *(Checkout Branch Price Reconciliation)* | `REQ-004`, `REQ-006`, `REQ-014`, `REQ-017`, `FR-014`, `TEST-019` | **Given** a customer browsed under Branch A's prices (`450,000 VND`), and at delivery checkout `POST /api/v1/storefront/orders/quote` auto-allocates Branch B (`470,000 VND`) where `priceChangedFromBrowsingBranch == true`, **when** the quote renders, **then** `CheckoutPriceReconciliationNotice` displays the price difference and disables the `Place order` button until the customer explicitly confirms the updated total. | Vitest + Playwright E2E (`TEST-019`) |
| **UI-AC-05** *(Order Snapshot Display)* | `REQ-005`, `REQ-006`, `FR-021`, `FR-031`, `TEST-007` | **Given** an existing order viewed on `/account/orders/:orderId` or `/admin/orders/:orderId`, **when** rendered, **then** it displays the traceable `processingBranchName` and reads line items strictly from `skuSnapshot`, `productNameSnapshot`, `unitPriceSnapshot`, and `lineTotalSnapshot`. | Vitest + Playwright E2E |
| **UI-AC-06** *(Webhook Payment Verification Non-Trust)* | `REQ-009`, `FR-025`, `TEST-011` | **Given** a customer lands on `/checkout/payment-status/:orderId` via browser redirect, **when** the page loads before the backend receives a verified server-side payment webhook, **then** the UI shows `Awaiting server payment verification` and never marks or implies the order is paid until the server status is `PAID`. | Vitest + Integration test (`TEST-011`) |
| **UI-AC-07** *(Admin Server Branch Scope & Cross-Branch Denial)* | `REQ-011`, `REQ-012`, `FR-006`, `TEST-013`, `TEST-014` | **Given** a staff user logged into `/admin` with `authorizedBranchIds = [Branch A]`, **when** the UI renders or an API call targeting Branch B returns `403 BRANCH_ACCESS_DENIED`, **then** the workbench locks the branch scope indicator to Branch A and `ProblemAlertBanner` displays the branch authorization boundary message clearly. | Vitest + Playwright E2E |
| **UI-AC-08** *(Non-Negative Stock & Dual-Side Transfers)* | `REQ-007`, `REQ-008`, `REQ-015`, `FR-018`, `FR-019`, `TEST-018` | **Given** the Admin Spoilage Adjustment or Stock Transfer Dispatch screen at Branch A (holding 3 units of SKU P), **when** a staff member enters a deduction of 5 units, **then** client validation blocks submission before sending, and if the server returns `409 INVENTORY_INSUFFICIENT_STOCK`, the UI displays the exact available stock (`3`) without crashing. | Vitest + Playwright E2E |
| **UI-AC-09** *(RFC 9457 Problem Details & All 4 View States)* | `NFR-008`, `NFR-013`, `CLAUDE.md` §5, §7 | **Given** any data-fetching screen in `storefront` or `admin`, **when** tested across `loading`, `empty`, `error` (`application/problem+json`), and `populated` states, **then** every state renders cleanly without `dangerouslySetInnerHTML`, raw stack traces, or layout shift. | Vitest component suite |
| **UI-AC-10** *(Accessibility & Responsive Floor)* | `NFR-013`, Hallmark Floor #4–#7, Taste-Skill §5 | **Given** any page rendered at `1440x900`, `1024x768`, `768x1024`, `390x844`, and `320px`, **when** audited, **then** there is zero horizontal overflow, every form input has an explicit `<label>`, every interactive control has an instant `:focus-visible` ring and `>= 44px` touch height on mobile, text contrast meets WCAG AA/AAA, and `prefers-reduced-motion: reduce` disables animations. | Hallmark `sloplint.mjs` / Taste-Skill `consistency.mjs` + Playwright accessibility checks |
| **UI-AC-11** *(Hallmark & Taste-Skill Anti-Slop Visual Floor)* | Hallmark Floor #1–#15, Taste-Skill House Rules #1–#9 | **Given** the compiled CSS and DOM of `storefront` and `admin`, **when** linted, **then** all colours/fonts come from `:root` tokens (`Garden` theme), there are zero `transition: all` rules, zero tracked all-caps eyebrows, zero purple/violet gradients, zero captions under floral photographs, and tabular numerals (`tabular-nums`) are applied to all prices and stock tables. | CSS & DOM lint check |
